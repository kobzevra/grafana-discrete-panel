# Production Timeline Panel Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the legacy Angular Natel Discrete implementation with a production-ready React panel plugin for Grafana OSS 13.1.1 that satisfies the project's interval, filtering, focus, tooltip, and legend contract.

**Architecture:** Pure TypeScript domain modules normalize and validate Grafana DataFrames, clip intervals to `[from,to)`, apply filters/focus, derive display classes, and compute legend statistics. React integrates with Grafana and renders diagnostics/options/legend/tooltip; Canvas 2D renders only already-transformed interval geometry.

**Tech Stack:** TypeScript, React, Grafana `PanelPlugin`, public `@grafana/data` / `@grafana/ui` APIs pinned to 13.1.1, Jest, Grafana create-plugin tooling, Canvas 2D.

**Spec:** `docs/superpowers/specs/2026-08-18-production-timeline-panel-design.md`

## Global Constraints

- Production runtime target: Grafana OSS 13.1.1.
- Plugin ID: `kobzevra-production-timeline-panel`.
- Plugin name: `Production Timeline`.
- `grafanaDependency` initially `>=13.1.1`.
- No Angular, `PanelCtrl`, `CanvasPanelCtrl`, `grafana/app/*`, jQuery, Moment.js, or `@grafana/toolkit` runtime/build dependency.
- Renderer consumes normalized DataFrames only; no vendor-specific parsing.
- Dashboard range is half-open `[from,to)`.
- Duration filters use original/current duration; legend uses visible clipped duration.
- Job colors are deterministic; state colors are fixed and stable.
- Exact overlapping conflicting intervals must never produce misleading exact totals.
- T01-T14 are mandatory executable acceptance fixtures.
- Preserve MIT license and upstream attribution.

- [ ] **Step 1: Make T04-T06/T11/T12/T14 fail**

- [ ] **Step 2: Implement display-class precedence**

Reserved explicit classes `gap/stale/unknown/offline` win. Otherwise `running + job` becomes job, `running without job` becomes `running-unresolved`, and non-running intervals map to normalized fixed states or `unknown`.

- [ ] **Step 3: Implement stable job hash**

Use a small explicit versioned 32-bit string hash and a checked-in fixed palette. The exact same normalized job key always maps to the same palette index.

- [ ] **Step 4: Implement focus transformation**

Keep selected job, replace other running job display classes with a single `other-jobs` class, and leave states untouched.

- [ ] **Step 5: Implement legend aggregation from visible intervals only**

States: duration, percentage, segment count. Jobs: duration, distinct runId count when available, segment count. Multi-machine percentage denominator is range length multiplied by visible machine count.
